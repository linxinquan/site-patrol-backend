## 二、环境故障：PostgreSQL 反复崩溃（进行中）

**现象**：后端进程（不是主进程）崩溃，异常码 `0xC0000142`（STATUS_DLL_INIT_FAILED），
日志伴随 `could not reserve shared memory region ... error code 487`。
**每次新建连接都会触发**（每个连接 = 一个新后端进程 = 需要分配共享内存）。

**已排除的原因**（逐个验证过）：

| 假设 | 验证方式 | 结果 |
|---|---|---|
| 内存不足 | 页面文件 14 GB 只用 973 MB，虚拟内存剩 14.2 GB | ❌ 不是 |
| 残留 postgres 进程 | `Get-Process postgres` | ❌ 进程数为 0 |
| 连接数过多 | 已改 `max_connections = 20` | ❌ 仍崩 |
| 并行查询占用动态共享内存 | 已改 `max_parallel_workers_per_gather = 0` | ❌ 仍崩 |
| DSM 类型不合适 | 试 `mmap`，该构建不支持 | ❌ 无效 |

**结论**：指向系统级资源耗尽或地址空间被占，**重启 Windows 通常能恢复**。

**已做的处置**：
- `postgresql.conf` 保留两项调整（`max_connections=20`、关闭并行查询）—— 本身是合理的本地开发配置
- 导入脚本从 `TRUNCATE` 改为逐表 `DELETE`（`TRUNCATE ... CASCADE` 曾直接把 PG 搞崩，
  而它要拿 ACCESS EXCLUSIVE 锁；`DELETE` 只要 ROW EXCLUSIVE，慢一点但稳）
- 导入脚本加了连接预检：连不上时直接打印可操作的提示，而不是甩一屏 traceback

**恢复步骤**：

```powershell
# 重启 Windows 后
& 'D:\tools\PostgreSQL\16\pgsql\bin\pg_ctl.exe' -D 'D:\tools\PostgreSQL\data' -l 'D:\tools\PostgreSQL\pg.log' start
```
